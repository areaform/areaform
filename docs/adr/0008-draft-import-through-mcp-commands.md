# Drafts are imported by an agent through Commands, not by a format converter

A first Draft of a plan can be made from a design source (a Figma mock-up, a scanned or rendered image) and then reviewed and corrected by a person in the Editor. The import is an MCP server, `packages/mcp`, that gives an agent (Claude) the headless core: it creates a Draft, applies batches of Commands, reads Diagnostics and renders a preview. The agent reads the source itself, through other tools such as the Figma MCP or by looking at an image, and decides what becomes a Wall, a Zone or an Opening. The server knows nothing about any source format.

We considered a deterministic converter per format (`import_figma(url) → Document`, mapping layers to Elements by rules). It is exact when a source follows its rules and useless when it doesn't, and real mock-ups rarely do. Every new source would need a new converter to write and maintain. With an agent on top of Commands, every step passes the same Invariants as an edit in the Editor, so the agent learns precisely what was rejected and why, and a new source needs no server change.

Converters are not ruled out but are demoted to helpers: `figma_extract` reads a Figma file through the REST API and, where layers follow a published naming convention, returns exact geometry in metres for the agent to turn into Commands. Without the convention or a `FIGMA_TOKEN`, the agent works from the Figma MCP and a screenshot alone.

The agent is not trusted to be right. Scale is never guessed: it comes from a two-point calibration, and the agent must ask when the source shows no known dimension. Anything uncertain is recorded as an Import Flag, and the source image is attached as a locked Underlay, so the reviewer sees the Draft over the original.

**Consequences:** the MCP server depends only on `core`, not on `render-2d` (PixiJS needs a DOM), so it draws its own SVG preview from `core` geometry and `wallOutlines` and rasterises it with resvg. Import bookkeeping lives in `document.meta.import`, so the model is unchanged; Walls, Openings and Obstacles have no data field of their own, and adding one is deferred until re-import needs it. A Draft is a folder (`plan.json` plus the source image, referenced by a relative `src`), so hosts resolve relative Underlay paths with `resolveAsset` on the View and Editor, and the Playground imports a whole folder. Quality cannot be unit-tested end to end; it is measured by a round trip of a known plan through Figma and back.
